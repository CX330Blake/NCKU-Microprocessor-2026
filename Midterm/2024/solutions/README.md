# 2024 微算機原理與應用期中考：PIC18F4520 詳解

依原始 `Midterm.pdf` 四頁、共九小題整理。環境：PIC18F4520、Microchip pic-as；VS Code 為編輯器。各題完整程式在同目錄的 `q1a.S` 至 `q3c.S`，每個檔案皆可獨立組譯、由 Reset 執行範例，最後停在 `done` 無窮迴圈。

**每次只編譯一題，不要把九個檔案連結在一起。** 各題刻意共用 RAM、Reset vector 與部分符號；1b 的 `Fact` 是巨集，1c 的 `Fact` 是副程式。

本文未標 `0x` 的一般計數及公式使用十進位；十六進位陣列均明確標示。

## 使用方式與共同觀念

1. 先讀題解，手算範例，再開相應 `.S` 逐行追蹤。
2. 修改 `main` 中的範例輸入；1b 修改 `Fact 5,3` 的常數參數。
3. 在除錯器於 `done` 設中斷點，檢查本題指定的 RAM。
4. 除 1a 會覆寫輸入工作暫存器外，其餘副程式的輸入保存方式詳見原始碼註解。

### pic-as 組譯命令

以下命令由本份 `README.md` 所在的 `solutions` 目錄執行。這些是此電腦已安裝的工具及 device pack 路徑；換電腦時應依實際安裝位置修改。

```sh
PIC_AS=/Applications/microchip/xc8/v3.10/pic-as/bin/pic-as
DFP=/Users/CX330/.mchp_packs/Microchip/PIC18Fxxxx_DFP/1.8.178/xc8
mkdir -p /tmp/ncku-midterm-build
"$PIC_AS" -mcpu=18F4520 -mdfp="$DFP" \
  -Wl,-presetVec=0h \
  -Wl,-Map=/tmp/ncku-midterm-build/q1a.map \
  -o /tmp/ncku-midterm-build/q1a.hex q1a.S
```

將命令中的 `q1a` 換成其他題號即可。`.S` 會經 C preprocessor 處理，才能使用 `#include <xc.inc>`。`-presetVec=0h` 將 Reset 程式區段放到位址 0；不要省略。

程式只設定 `WDT=OFF`、`LVP=OFF`、`XINST=OFF`，其他 configuration bits 使用工具預設，因此會出現 `(1311) missing configuration setting` 警告。這不是組譯失敗；但燒錄實體板之前，仍須依板子設定 oscillator 等 configuration bits。本解答已做指令級模擬，未做實體板驗證。

### 必須先懂的 PIC18 語意

| 寫法／概念 | 正確解讀 |
|---|---|
| `movf file,0,0` | 第二個運算元 `d=0`：結果送 WREG；最後的 `a=0`：Access Bank |
| `addwf file,1,0` | `d=1`：結果寫回 file；本解答用數字避免 `w`／`f` 未定義問題 |
| `subwf file,0,0` | 計算 `file - WREG`，不是反過來 |
| 減法後 `C=1` | 沒有借位，即原本 `file >= WREG`（unsigned） |
| `rlcf`／`rrcf` | 經 Carry 旋轉，不是自動補零／補符號的純位移 |
| `addwfc` | 將低位元組加法的 Carry 加進高位元組 |
| `lfsr 0,0x300`、`INDF0` | FSR 保存完整 RAM 位址，以間接定址存取資料 |
| `POSTINC0`／`POSTDEC0` | 存取 FSR0 指向的資料後，自動增加／減少指標 |
| `mulwf` | unsigned 8×8 乘法，16-bit 結果放在 `PRODH:PRODL` |

PIC18F4520 在 `XINST=OFF` 時，Access Bank 的一般 RAM 範圍為 `0x000..0x07F`，另有高位 SFR 區。`a=0` **不表示可以直接存取任意 bank**：例如陣列 `0x300` 須用 FSR，不能把 `movwf 0x300,0` 當成寫入 RAM `0x300`。

本解答以 `EQU` 指定獨立程式的固定 RAM 工作區；`EQU` 不會向 linker 保留記憶體，因此組譯摘要可能顯示 Data space used 為 0。若日後與其他模組整合，需重新配置／保留 RAM，不能原樣混用。

## 1a（15%）：16-bit 除以 8-bit

完整程式：[q1a.S](q1a.S)。

### 介面

- 輸入：`qhi:qlo = [0x30]:[0x31]`，除數 `[0x32]`。
- 輸出：商高位元組 `[0x20]`、商低位元組 `[0x21]`、餘數 `[0x22]`。
- 假設 unsigned，且除數不為 0。試卷未定義除以零的結果，本程式不替它發明答案。

### 解法：二進位長除法

由最高位到最低位取出被除數的 16 個 bit。每輪把下一個 bit 接到目前餘數後面；若餘數不小於除數，就扣掉除數，並將本輪的商設為 1。

```text
remainder = 0
quotient = dividend
repeat 16 times:
    next_bit = old bit 15 of quotient
    quotient = (quotient << 1) & 0xFFFF
    wide_remainder = (remainder << 1) | next_bit
    if wide_remainder >= divisor:
        wide_remainder -= divisor
        quotient |= 1
    remainder = wide_remainder
```

程式用 `qhi:qlo` 同時保存尚未處理的被除數及逐步建立的商，因此不用另外配置 16-bit 商暫存器。

**最容易錯的地方：中間餘數需要 9 bits。** 每輪開始 `remainder < divisor <= 255`，但左移接 bit 後可能到 509。`rlcf rem8,1,0` 移出的 Carry 就是第九位；若它是 1，代表中間值至少 256，一定要減除數。不能只比較截成 8 bits 的 `rem8`。

範例：

\[
0x0406 = 1030 = 3\times343+1 = 0x03\times0x0157+0x01.
\]

因此 `[0x20]=0x01`、`[0x21]=0x57`、`[0x22]=0x01`。

複習重點：16-bit 位移必須低位元組先 `RLCF`、再高位元組，將兩者用 Carry 接起來；固定執行 16 輪。

## 1b（15%）：以 `Fact` 巨集計算組合數，n ≤ 8

完整程式：[q1b.S](q1b.S)。使用方式：`Fact 5,3`。

### 不要直接算階乘

\[
C(n,k)=\frac{n!}{k!(n-k)!}.
\]

這是數學定義，不代表實作一定要先算階乘。雖然答案最多只有 `C(8,4)=70`，`8!=40320` 卻早已超過 8 bits。

### 解法：Pascal recurrence

\[
C(n,k)=C(n-1,k-1)+C(n-1,k),\qquad C(n,0)=C(n,n)=1.
\]

工作陣列 `a[0..8]` 放在 `0x40..0x48`，初始化 `a[0]=1`、其餘為 0。

```text
for row = 1 to n:
    for j = row down to 1:
        a[j] = a[j] + a[j-1]
answer = a[k]
```

**一定要從右往左更新。** 這樣 `a[j-1]` 還是上一列的值；從左往右會讀到已更新的本列資料。

以 `n=5,k=3` 為例，Pascal 各列為：

```text
1
1 1
1 2 1
1 3 3 1
1 4 6 4 1
1 5 10 10 5 1
```

最後 `a[3]=10=0x0A`，存到 `[0x00]`。

本題巨集的 `nn,kk` 是組譯時的常數參數；巨集展開後直接執行計算，**不是呼叫名為 Fact 的副程式**。`LOCAL` 使內部標籤每次展開都有獨立名稱，避免多次使用巨集時撞名。

## 1c（5%）：以 `Fact` 副程式計算組合數，n ≤ 15

完整程式：[q1c.S](q1c.S)。

- 輸入：`[0x10]=n`、`[0x11]=k`。
- 執行：`call Fact`。
- 輸出：`[0x00]` 高位元組、`[0x01]` 低位元組。

同樣使用 Pascal recurrence，但工作陣列改成 16 個 16-bit 數，位於 `0x100..0x11F`。工作表內每一項採低位元組在前；最後輸出時再依題目要求存成高位元組在前。

\[
\max_{0\le k\le n\le15} C(n,k)=C(15,7)=6435=0x1923<65536.
\]

所以全部合法輸入都能安全以 16-bit 相加計算；不需保存巨大階乘。

16-bit 加法的核心是：

```asm
    movf POSTINC1,0,0
    addwf POSTINC0,1,0
    movf INDF1,0,0
    addwfc INDF0,1,0
```

低位元組用 `ADDWF`，高位元組用 `ADDWFC`。中間的 `MOVF` 不會破壞 Carry。FSR0 指向目前項目，FSR1 指向前一項。

範例：`n=0x0A=10`、`k=0x04=4`，故

\[
C(10,4)=210=0x00D2,
\]

得到 `[0x00]=0x00`、`[0x01]=0xD2`。

題目的 recursive approach 是提示，不是強制要求。這裡將相同遞迴關係改成迭代 DP，避免遞迴呼叫時保存 n、k、中間結果及返回狀態的複雜度。邊界 `n=0,k=0` 與 `k=0` 都會正確回傳 1。

## 2a（15%）：原地反轉指定子陣列

完整程式：[q2a.S](q2a.S)。

- 陣列：`[0x300]..[0x309]`。
- 輸入：`[0x10]=head`、`[0x11]=tail`，皆為 **索引**，不是 RAM 位址。
- 前提：`0 <= head <= tail <= 9`。
- 輸出：直接修改原陣列，區間之外保持不變。

### 解法：雙指標

```text
left = 0x300 + head
right = 0x300 + tail
while left < right:
    swap(memory[left], memory[right])
    left += 1
    right -= 1
```

以 FSR0 和 FSR1 分別指向左右端，交換 `INDF0`、`INDF1`。兩個指標都不離開 bank 3，因此此特定題目比較指標低位元組就足夠。

範例 `head=3,tail=6`，交換索引 `(3,6)`、`(4,5)`，結果為：

```text
[0x65, 0x06, 0x03, 0xF7, 0x04, 0x0C, 0x65, 0x32, 0x50, 0x00]
```

`head=tail=7` 時一個元素都不必交換，原陣列不變。判斷應是 `left < right`，而不是必須等到兩者恰好相等才停止；偶數長度區間的指標會直接交錯。

## 2b（15%）：兩串列的對稱差集

完整程式：[q2b.S](q2b.S)。

- A：`0x100..0x102`；B：`0x110..0x112`。這些是本解答選定的輸入位址，試卷未指定輸入位址。
- 結果從 `[0x00]` 依序儲存。
- 額外將輸出數量放在 `[0x20]`，便於知道哪些 RAM 位元組有效；它不是題目要求的終止符。

要找的是：

\[
A\triangle B=(A\setminus B)\cup(B\setminus A).
\]

```text
for each value in A:
    if value does not occur in B:
        append value
for each value in B:
    if value does not occur in A:
        append value
```

範例 A=`[0x08,0x09,0x02]`，B=`[0x02,0x03,0x04]`。共同元素 `0x02` 不輸出，答案為 `[0x08,0x09,0x03,0x04]`，存到 `0x00..0x03`，`[0x20]=4`。

**不是把所有值串接後只刪掉第二次出現的值。** 那樣會留下共同元素的一份，是聯集，不是對稱差集。

每個串列內部保證沒有重複，因此不需另外去重。數值 `0x00` 仍是合法資料，不能拿它當作結束標記；只看輸出數量。有效輸出長度只能為 0、2、4、6；題目保證至少一個獨有元素，所以合法考題的長度為 2、4、6。本程式也可處理兩集合相同的額外邊界情況。

## 2c（5%）：同樣四個十六進位數字的下一個排列

完整程式：[q2c.S](q2c.S)。

- 輸入：`[0x10]:[0x11]`，高位元組在前。
- 輸出：`[0x00]:[0x01]`，高位元組在前。
- 額外旗標 `[0x20]=1` 表示有解。
- 試卷未定義無解時應輸出什麼。本解答約定：若已是最大排列，保留原值並設旗標為 0，**不循環回最小排列**。

### 解法：next permutation

先拆成從高到低的四個 nibble `d[0],d[1],d[2],d[3]`。

1. 從右向左，找第一個 `d[i] < d[i+1]` 的位置 i，稱為 pivot。
2. 若沒有 pivot，整串已是非遞增排列，因此不存在更大排列。
3. 從最右側找第一個 `d[j] > d[i]`，交換兩者。
4. 將 i 右側的後綴反轉，讓它變成非遞減排列。
5. 把四個 nibble 組回 16-bit 數。

例一：`0x1234`，pivot 是 3，與 4 交換，得到 `0x1243`。

例二：`0x1AC3`：

- 由右看 `C >= 3`，不能增加這一位；再看 `A < C`，故 pivot 為 A。
- 右側大於 A 的最小數字為 C，交換後是 `1 C A 3`。
- 後綴 `A 3` 反轉成 `3 A`，得到 **`0x1C3A`**。

為何最小？選最右側可增加的位置，保留最多高位不變；以最小的較大數字取代 pivot；再把後綴排到最小。三步一起保證「大於原值」且「增量最小」。

不能只排序全部數字，也不能固定交換最後兩位。比較必須是嚴格 `<`／`>`，才能正確處理重複數字，例如 `0x1121 → 0x1211`。固定四個 nibble 包含前導零，例如 `0x0010 → 0x0100`。

## 3a（15%）：邏輯左移、算術右移、nibble 乘法

完整程式：[q3a.S](q3a.S)。

設輸入 `x=[0x00]`：

\[
a=(x\ll2)\bmod256,\quad
b=\operatorname{ASR}_8(a,3),\quad
c=(b\ll2)\bmod256.
\]

依序存到 `0x01`、`0x02`、`0x03`。**第二步對第一步的結果操作，第三步對第二步的結果操作，不是都從原始 x 開始。**

### 邏輯左移

每次左移前清除 Carry，再執行 `RLCF`；移出的最高位直接捨棄。要移兩位，就重複兩次，兩次都先清 Carry。

### 算術右移

每次右移前先把目前 bit7 複製到 Carry，再用 `RRCF`。這樣新的 bit7 才會等於原本符號位，達成 sign extension。

```asm
    bcf STATUS,0,0
    btfsc SHIFT_ARITH,7,0
    bsf STATUS,0,0
    rrcf SHIFT_ARITH,1,0
```

這段要執行三次。不是只在第一輪設定 Carry，因為 `RRCF` 會將原本 bit0 移到 Carry。

範例 `x=0x93`：

```text
10010011 << 2 = 01001100 = 0x4C
01001100 ASR 3 = 00001001 = 0x09
00001001 << 2 = 00100100 = 0x24
```

注意：這個範例的 `0x4C` 符號位為 0，不能單靠它驗證算術右移。另取 `x=0x20`，第一步 `0x80`，算術右移三位應為 `0xF0`，不是 `0x10`；最後左移得 `0xC0`。

### nibble 乘法

對 a、b、c 分別計算：

\[
\operatorname{product}(v)=((v\gg4)\mathbin{\&}0x0F)\times(v\mathbin{\&}0x0F).
\]

以 `SWAPF` 和 `ANDLW 0x0F` 取得高 nibble，以 `ANDLW 0x0F` 取得低 nibble，再 `MULWF`。最大乘積 `15×15=225`，放得進一個 byte。

範例的乘積為 `0x4×0xC=0x30`、`0x0×0x9=0x00`、`0x2×0x4=0x08`，依序存到 `0x11`、`0x12`、`0x13`。

## 3b（10%）：CRC-16 多項式長除法

完整程式：[q3b.S](q3b.S)。

- 輸入 8-bit message 放在 `[0x10]`。
- CRC 高位元組放 `[0x00]`，低位元組放 `[0x01]`。
- 生成多項式：

\[
P(x)=x^{16}+x^{12}+x^5+1=0x11021.
\]

**CRC 是 GF(2) 上的多項式除法，減法使用 XOR，不是一般整數的減法。** 依試卷圖示，要先在 message 後面補 16 個 0。

此題的明確參數為：MSB-first、初始 seed 0、不反射、無最終 XOR。不能只說「CRC-16」就套用某個函式庫預設；同一多項式搭配不同參數會有不同答案。

### 16-bit 暫存器實作

```text
crc = message << 8
repeat 8 times:
    old_top = crc & 0x8000
    crc = (crc << 1) & 0xFFFF
    if old_top != 0:
        crc ^= 0x1021
```

`0x11021` 是完整的 17-bit 除數；程式中的 `0x1021` 是去掉最高的 `x^16` 項。最高項是否需要消去，已由移出 bit15 的 Carry 決定，不是漏寫了一位。

為何只做 8 輪？先把 message 放在 CRC 暫存器高 byte，八次位移即完成對 `message << 16` 的除法。**這種表示法不可再多做 16 輪**，否則相當於多補了零。

範例 `message=0xFE`，CRC 暫存器從 `0xFE00` 開始，八輪依序為：

```text
0xEC21 → 0xC863 → 0x80E7 → 0x11EF →
0x23DE → 0x47BC → 0x8F78 → 0x0ED1
```

答案 `[0x00]=0x0E`、`[0x01]=0xD1`。若要組成含資料與 CRC 的傳送內容，會是三個 byte `FE 0E D1`；題目要求存的是兩個 CRC byte。

## 3c（5%）：最小 Y，使 Y OR (Y+1) = X

完整程式：[q3c.S](q3c.S)。

- 輸入：`[0x10]=X`，且 X 為 `2<X<256` 的質數。
- 輸出：最小 Y 放在 `[0x00]`。

### 考場實作：從小到大搜尋

```text
Y = 0
while (Y | (Y + 1)) != X:
    Y += 1
answer = Y
```

因為按遞增順序搜尋，第一個符合者必定最小。合法 X 都是奇數，所以 `Y=X−1` 一定成立：偶數 X−1 的 bit0 為 0，與 X 做 OR 就是 X。因此搜尋必定在 `0..X−1` 內結束，不會發生 8-bit 加法溢位。

原碼用 `INCF` 算 Y+1、`IORWF` 做 OR、`XORWF X` 後判斷 Z。這是 bitwise OR，不能用加法或 XOR 取代。

題目範例（此處數字皆為十進位）：

| X | 最小 Y | 位元驗算 |
|---|---|---|
| 5 | 4 | `0100 OR 0101 = 0101` |
| 7 | 3 | `0011 OR 0100 = 0111` |
| 11 | 9 | `1001 OR 1010 = 1011` |

### 進階推導：不用窮舉的公式

設 X 的最低位開始連續有 t 個 1，則：

\[
Y_{\min}=X-2^{t-1}.
\]

理由：若 Y 結尾有 r 個連續的 1，則加 1 會把這 r 個 1 清零，並將上方的 0 改為 1。兩者 OR 後，最低 r+1 位全為 1；其他位相同。故 Y 相較 X 恰好少了 bit r，必須 `r <= t−1`。要讓 Y 最小，就清掉可清除的最高位 `t−1`。

例如 `X=7=0b111`，t=3，故 `Y=7−4=3`；`X=11=0b1011`，t=2，故 `Y=11−2=9`。實作仍採簡單搜尋，避免為此 8-bit 題目增加位元處理的複雜度。

## 驗證結果

使用本機 pic-as（XC8 v3.10）及 PIC18Fxxxx_DFP 1.8.178 組譯，九題皆成功產生 HEX。以 gpsim 0.32.1 的 PIC18F4520 指令模擬執行實際 HEX，不只是執行另一份高階語言演算法。

另外，九題各自由 Reset 執行 `main` 的內建範例，到 `done` 讀取 RAM，結果皆符合試卷範例。以下為可變輸入的模擬測試覆蓋：

## 建議複習順序

先做 3a 熟悉 Carry、位移與 `MULWF`；再做 2a/2b 熟悉 FSR、迴圈及比較；接著做 1a、1b/1c；最後做 2c、3b，並用 3c 練習最小值證明。

完成複習的標準不是背下範例輸出，而是能回答：

- 每一條比較指令到底在計算誰減誰？C=1 是什麼意思？
- 哪些指令會改 Carry？哪一輪需要先清 Carry 或複製符號位？
- 中間值需要多少 bits，而不是只有最終答案需要多少 bits？
- FSR 指向哪裡？存取後指標有沒有自動改變？
- 如何證明演算法不只找到一個解，而是找到題目要求的最小解？
