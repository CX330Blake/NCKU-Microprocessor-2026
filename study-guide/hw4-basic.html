7. 巨集 Mul_Add：x1×x2 + y1×y2

題目描述解題思路範例追蹤完整程式碼與解釋易錯點自我檢查

01 / 題目到底要做什麼？

實作並呼叫 Mul_Add x1, x2, y1, y2 巨集。四個輸入都是 8 位元無號整數，依序放在 [0x000]=x1、[0x001]=x2、[0x002]=y1、[0x003]=y2。分別求 x1×x2 與 y1×y2；每個乘積皆須視為 16 位元，再以 16 位元加法求和。題目保證最後總和不超過 65535。結果高位元組寫入 [0x010]，低位元組寫入 [0x011]。PDF 範例一為 FF×02+80×03=037E，範例二為 DC×A0+B0×30=AA80。注意：目前 basic.S.bak 雖預設 TEST_CASE=2，實際載入的是自訂 48、06、5A、04，不是 PDF 範例二。

02 / 從題意推導程式

  1. 先把 x1 放進 WREG，再以 MULWF x2 產生 PRODH:PRODL；將兩個位元組立即複製到輸出，因為第二次 MULWF 會覆寫乘積暫存器。
  2. 第二個乘積的低位元組加到 [0x011]；若低位元組相加超過 FF，STATUS.C 便是高位元組需要的進位。
  3. MOVF PRODH,W 只更新部分旗標，不會破壞 Carry，接著 ADDWFC 將第二個高位元組及前一筆進位一起加到 [0x010]。
  4. 巨集在組譯時展開，不需要 CALL/RETURN；參數是 RAM 位址，不是直接把四個常數寫進算術式。此版本使用 Access Bank，呼叫時四個輸入都須位於可用的 access RAM。

03 / 跟著範例走一次

以下為依程式語意整理的手算追蹤；不是本次重新執行 PIC 模擬器的結果。

階段／狀態數值為何變成這樣
目前預設輸入x1=0x48=72，x2=6，y1=0x5A=90，y2=4TEST_CASE=2 分支的實際常數。
第一個乘積72×6=432=0x01B0[010]=01、[011]=B0。
第二個乘積90×4=360=0x0168PRODH=01、PRODL=68。
低位相加0xB0+0x68=0x118[011]=18，Carry=1。
高位相加0x01+0x01+1=0x03[010:011]=0x0318，即 792。
PDF 範例二對照0xDC×0xA0=0x8980；0xB0×0x30=0x2100相加得到 0xAA80；這不是目前預設輸入的答案。

05 / 最容易踩的坑

  • 不能只把兩個 PRODL 相加；8×8 的結果可達 65025，必須保留 PRODH。
  • 低位 ADDWF 與高位 ADDWFC 之間不能插入會改寫 C 的算術或旋轉指令；本程式的 MOVF 可保留 C。
  • 檔名 .S.bak 是備份原始碼；是否納入目前專案建置取決於專案設定，不可只因看見檔案就假定會執行它。
  • 第 4 行註解宣稱 TEST_CASE=2 對應 AA80，但第 35–42 行已換成自訂值，閱讀時以實際指令為準。

06 / 確認自己真的懂了

為什麼第二次乘法前就要複製第一個乘積？

兩次乘法共用 PRODH:PRODL，第二次會覆寫第一個值。

目前預設程式結束時應觀察哪兩格，數學推導值為何？

觀察 [0x010]=0x03 與 [0x011]=0x18；這是自訂輸入的 792，非 PDF 範例二 AA80。

若低位相加沒有進位，ADDWFC 還能用嗎？

可以；此時 C=0，它等同高位相加。
