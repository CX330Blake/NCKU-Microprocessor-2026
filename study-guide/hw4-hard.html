9. 分數計算機：三個分數、兩個運算子、化簡

題目描述解題思路範例追蹤完整程式碼與解釋易錯點自我檢查

01 / 題目到底要做什麼？

以無號整數完成三個分數、兩個運算子的分數計算器：A/B op1 C/D op2 E/F。A、B、C、D、E、F 都是 8 位元無號數，依序位於 [0x000]–[0x005]，分母不為零；[0x006]、[0x007] 為 op1/op2，編碼 00=加、01=減、02=乘、03=除。必須以 fractionCalc 子程式做一次兩分數運算，並呼叫 GCD 子程式將每次運算結果約成最簡分數，才可繼續下一次計算。乘除優先於加減，同級由左至右。最後分子以 16 位元高／低位存到 [0x010]/[0x011]，分母高／低位存到 [0x012]/[0x013]。題目保證減法結果非負且非零，除數分數非零，所有需要的中間值與最後值都在 0–65535，且不會出現零分母。PDF 範例一為 C7/E9 + 11/05 × 03/28 = C9E3/B608；範例二為 71/1B − B4/C4 ÷ F3/31 = 0004/0001。目前 TEST_CASE=2 實際載入自訂 65/17 − 2E/0B + AB/3E，並非 PDF 範例二。

02 / 從題意推導程式

  1. 先判斷優先序：運算碼的 bit1 在加減時為 0、乘除時為 1。只有 op1 是加減且 op2 是乘除時先算右邊；其他組合一律先算左邊，因此同級自然由左至右。
  2. leftN/leftD 與 rightN/rightD 都擴為 16 位元。乘法計算 (a×c)/(b×d)，除法計算 (a×d)/(b×c)，加減則先算交叉分子 a×d、c×b 與共同分母 b×d，再做 16 位元加減。
  3. Multiply16 使用三次硬體 8×8 乘法：保留 al×bl 的完整 16 位元，將 ah×bl 與 al×bh 的低位加進結果高位。ah×bh 只影響 bit16 以上；由題目保證乘積可放入 16 位元，不需要保留那些位元。
  4. 每次 fractionCalc 先用 Euclid 餘數法算 gcd(resultN,resultD)，再分別除以同一個 GCD，把最簡分數寫回 leftN/leftD。rightN/rightD 與原輸入 RAM 保留。
  5. divide16 是固定 16 次的恢復式長除法：將被除數逐位左移送入餘數，試減除數；無借位時接受差並將本輪商位設成 1，有借位時保留原餘數、商位維持 0。
  6. 先右算時，第一次結果原本在 left，必須先搬到 right 再重新載入第一個分數作 left；否則原本的右側子算式會被覆寫。

247–250
divideLoop:
    bcf STATUS, 0, a
    rlcf quotientL, f, a
    rlcf quotientH, f, a
divideLoop 每輪清 C，再把 quotientL、quotientH 串接左移；舊 bit15 留在 C，商 bit0 先補零。
251–252
    rlcf remainderL, f, a
    rlcf remainderH, f, a
再左移 remainderL、remainderH，把剛才的被除數最高位經 C 送入餘數低位。
253
原檔空行／註解；用於分隔段落或標示背景，不執行指令。
254–256
    movf divisorL, w, a
    subwf remainderL, w, a
    movwf differenceL, a
以 remainderL−divisorL 試減，差值低位暫存到 differenceL，C 保存低位是否借位。
257–260
    movf divisorH, w, a
    subwfb remainderH, w, a
    movwf differenceH, a
    bnc nextDivisionBit
高位以 SUBWFB 接續借位，暫存 differenceH；最終 C=0 表示整個餘數不足，跳過接受差值。
261–264
    movff differenceH, remainderH
    movff differenceL, remainderL
    bsf quotientL, 0, a
nextDivisionBit:
試減成功才把 difference 寫回 remainder 並設 quotientL.bit0=1；nextDivisionBit 是成功與失敗的共同出口。
265–268
    decfsz bitCount, f, a
    bra divideLoop
    return
END resetVec
bitCount 減至零才 RETURN，否則繼續處理下一位；END resetVec 結束原始碼。

05 / 最容易踩的坑

  • 檔首註解仍把 case 2 寫成 4/1，但實際預設資料已改；不可把 4/1 當成目前程式的輸出。
  • operation 是 0–3 的數值編碼，不是 ASCII 的 +、-、*、/；bit1 的優先序判斷只在這個編碼約定下成立。
  • PIC18 減法 C=1 表示「沒有借位」；BNC 因而是餘數不足、不能採用試減結果的分支。
  • Multiply16 的來源與目的不可重疊。它只保留低 16 位，並不檢查溢位；正確性依賴題目對完整中間乘積的範圍保證。
  • 約分只能在得到本次分子與分母後進行；不能把前一次未約分的巨大值直接帶入下一次，並指望最後才約分。
  • 此計算器沒有負數、非法運算碼與零除錯誤處理；題目約束排除了這些情形，不應把它解讀成通用分數函式庫。
  • 工作暫存器全在固定 access RAM 020–03B；子程式會改寫共享暫存與 STATUS，不可不加保存地並行或由中斷重入。

06 / 確認自己真的懂了

為何 A/B ÷ C/D × E/F 要走 leftFirst？

乘除同級，題目要求從左到右；不能任意把除法右側重新結合。

為什麼 divide16 要用 difference 暫存，而不是立刻改寫 remainder？

試減可能借位；先保留差，只在 C=1 時提交，可在失敗時直接保留原餘數。

GCD(0,d) 在這段 Euclid 實作中如何處理？

只要 d 非零，先做 0÷d 得餘數 0，再更新成 (d,0)，因此回傳 d；可以把零分子約成 0/1，雖題目減法案例排除零結果。

最終 RAM 和工作區的高低位規則一致嗎？

一致：HW4 的工作配對與 010–013 都是先高位後低位；這與 HW5 的 XC8 unsigned int 參數槽 little-endian 不同。
