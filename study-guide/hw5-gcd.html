10. C 呼叫組語 gcd(unsigned char a, unsigned char b)

題目描述解題思路範例追蹤完整程式碼與解釋易錯點自我檢查

01 / 題目到底要做什麼？

讓 C 的 main.c 呼叫以 PIC18 組合語言實作的 gcd，介面固定為 extern unsigned char gcd(unsigned char a, unsigned char b);。兩個輸入均是 1–255 的 8 位元無號數，回傳最大公因數為 unsigned char，並把結果放在名稱為 ans 的 unsigned char 變數中，於 Watches 視窗展示。PDF 範例為 gcd(5,10)=5、gcd(252,105)=21、gcd(17,5)=1。題目使用 gcd.asm 這個檔名描述；此專案實際來源為可經前處理的 gcd.S。目前 main.c 呼叫 gcd(144,233)，不是 README 所寫的 gcd(252,105)，數學答案為 1。

02 / 從題意推導程式

  1. 先遵守此 XC8 專案的混合語言呼叫約定：第一個 unsigned char 由 WREG 傳入，第二個由連結器符號 _gcd$1 傳入；入口立即複製到自己的兩個 access-bank 工作位元組。
  2. 使用減法版 Euclid：gcd(a,b)=gcd(a−b,b)（a>b），或 gcd(a,b−a)（b>a）。每次只減較大者，因此正值不會變負，且兩數總和持續減少。
  3. 先計算 a−b 到 WREG，不改原 a。Z=1 代表兩者相等，可以返回；否則 C=1 代表 a>b，可直接把試減差寫回 a。C=0 代表 a<b，重新計算 b−a 寫回 b。
  4. 相等時的共同值就是 GCD。把它寫到 WREG，也寫回 _gcd$1 參數／返回槽，使 C 呼叫端取得結果；C 用 volatile ans 保留可觀察儲存，最後停在空迴圈。

03 / 跟著範例走一次

以下為依程式語意整理的手算追蹤；不是本次重新執行 PIC 模擬器的結果。

階段／狀態數值為何變成這樣
目前呼叫gcd(144,233)WREG=144，_gcd$1=233，複製後 (a,b)=(144,233)。
首輪比較144−233 借位，C=0、Z=0走減 b 分支，b←233−144=89。
第二輪144−89=55，C=1、Z=0直接把 WREG 的 55 寫回 a。
持續縮小(55,89)→(55,34)→(21,34)→(21,13)→(8,13)每輪只替換較大的數。
最後幾輪(8,5)→(3,5)→(3,2)→(1,2)→(1,1)兩數總和下降，最後相等。
返回a−b=0 → Z=1，回傳 1WREG 與 _gcd$1 都為 1，C 的 ans=1。
PDF 對照(252,105)→(147,105)→(42,105)→(42,63)→(42,21)→(21,21)改用該組參數時答案才是 README 展示的 21。

05 / 最容易踩的坑

  • 不能把 _gcd$1 當作硬編碼 RAM 位址；它是由 XC8 連結器配置的符號，與 C 介面相連。
  • SUBWF gcd_a,w 計算的是 gcd_a−WREG，不是 WREG−gcd_a；C=1 是無借位。
  • 只要其中一個輸入為 0 而另一個非零，減法版會不停減零，無法收斂；題目限定 1–255，這個版本沒有零值防護。
  • gcd_a/gcd_b 是靜態共享工作區，不是每次呼叫獨立的堆疊區；不可由中斷與主程式同時重入。
  • README 的預設呼叫與 ans=21 文字已落後於 main.c。README 過去記錄的編譯／測試屬歷史說明，不代表本次教學重新執行。

06 / 確認自己真的懂了

為何 a>b 分支不需要再執行一次 SUBWF？

比較時已把 a−b 算到 WREG，BC 跳轉不改它，直接 MOVWF gcd_a 即可。

為何等值分支一定要先於 BC？

相等時 C 同樣為 1；若先當作較大者去減，就會把 a 變成零並破壞正值收斂條件。

volatile 能讓 gcd 函式可重入嗎？

不能；volatile 只約束 C 對 ans 的存取最佳化，不會替組語共享暫存提供保存或同步。
